## CRITICAL FIXES — DO NOT REVERT

Two fixes in `LayoutCanvas.tsx` are load-bearing. Reverting either will blank the canvas on iPhone Safari with no error.

**Fix 1 — Deferred Stage init**
`containerSize` initializes to `null`. The Konva Stage is not rendered until a ResizeObserver fires with real dimensions. This prevents premature canvas allocation.

**Fix 2 — Pixel ratio cap**
`pixelRatio={Math.min(window.devicePixelRatio, 2)}`. On iPhone 12+ (DPR=3), uncapped Konva creates ~33 MB of canvas backing stores. iOS Safari enforces a silent ~16 MB per-page canvas budget. The cap holds total canvas memory to ~5 MB on device.

Root cause was discovered 2026-05-23 after multiple sessions of misdiagnosis. These two lines are the difference between a working app and a blank screen on iPhone. They are not optimization — they are correctness.

## VERCEL PIPELINE — WHAT HAPPENED AND CURRENT STATE

During a Vercel project settings reconnect/disconnect earlier today, the `Root Directory` setting was disrupted. Vercel began reading `vercel.json` from the repo root instead of `frontend/`, and rejected an invalid `rootDirectory` field in that file, producing `[0ms]` build failures.

Fix: removed `rootDirectory` from `vercel.json` (it belongs in Vercel project settings, not in the file). Auto-deploy confirmed working immediately after.

**Current pipeline state:** Healthy. Push to `main` → production deploy → `rn-layout-engine.vercel.app` updated. Verified 2026-05-23.

## STRATEGIC CONCERNS

**No persistence = no operational use yet.** The tool is in validation mode only. Any real event layout created today is lost on browser refresh. This is the single largest gap between current state and operational readiness.

**Two Vercel projects is a governance risk.** Both serve the same code today. If the `frontend` project receives a manual deploy by mistake, it will silently diverge. The only fix is deletion.

**Mobile drawing is not supported.** Touch pan and zoom work. Touch drawing (line, arrow, text) does not. Primary mobile use case is reviewing and sharing layouts, not creating them — this is acceptable for current phase.
